# 返修机故障占比估算（FastAPI + NumPy）

备件前估算一批返修机中**电源 / 驱动 / 控制**三类故障各有多少台。
上传含「机器编号 + 分类器初判」的 CSV（≤500 台），维修班组随机拆检、
按台登记/更正/撤回实检类别，系统按实检样本拟合未检件的故障占比，
折算台数后加上各类实检数给出全批估计。

## 一、估算口径

1. 对已拆检机器，按**实检类别**分组，统计每组中各初判类别的经验概率，
   组成 3×3 混淆概率矩阵 `P`（行=实检，列=初判，每行和为 1）。
2. 未检件的初判经验分布为 `q`（各类未检件初判计数 / 未检台数，和为 1）。
3. 在单纯形约束 `π ≥ 0`、`Σπ = 1` 下，用 NumPy 求使平方误差
   `SSE = ‖Pᵀπ − q‖²` 最小的故障占比 `π`。求解器枚举内部点（等式 KKT）、
   三条边（一维解析解）和三个顶点，取 SSE 最小的可行解，矩阵亏秩时
   仍保证有候选返回（见 `app/estimation.py:_solve_simplex`）。
4. 各类估计台数 = 实检台数 + `π_k × 未检台数`（三类折算之和守恒为未检总数）。

### 门控规则

- **仍有未检件**时，若任一故障类别没有实检样本，或混淆矩阵不满秩
  （`numpy.linalg.matrix_rank` < 3），**撤下估数**并在页面提示补检原因。
- **全部拆完**时不做拟合，直接返回各类实检实数。
- 撤回一台后该台立即重新计入未检，门控与估数随之重算。

### 并发与一致性

- 拆检记录保存在单进程内存中，所有读写经同一把 `asyncio.Lock` 串行化。
  两个浏览器窗口同时登记/更正/撤回（含同一台机器）时，两笔修改都不丢失，
  接口返回的机器明细、实检数与估数始终来自持锁期间的同一份快照。
- 因此部署固定 `uvicorn --workers 1`（见 `docker-compose.yml`）；
  多进程/多副本需换成数据库等共享存储。

### 换批与乐观并发控制

- **每次成功上传 CSV 都另开一个新批次**：分配单调递增的批次 ID
  （`B0001`、`B0002` ……），清空全部拆检记录；重传同一份 CSV 也一样。
- 所有快照（上传响应与 `GET /api/batch`）都带 `batch_id`，页面在
  上传卡片、估算卡片和登记卡片三处显著显示当前批次号。
- 登记/更正/撤回请求必须携带点击时页面显示的 `batch_id`。若写入前
  批次已被另一窗口的上传替换，后端返回 **HTTP 409**
  （`code=batch_switched`，并带回 `current_batch_id`），**拒绝写入**：
  旧批的登记不会落到新批的同号机器上。前端弹出换批提示、显示当前
  批次并自动同步新批清单，等班组在当前批次重新操作。
- 前端维护单调请求序号：只接受最新一次请求的响应，迟到的旧批响应
  （无论 200 还是 409、GET 还是 POST）一律丢弃，不能把页面恢复成
  旧清单或旧估数。3 秒轮询发现批次号变化时整体切换到新批并给出横幅。
- 混淆矩阵 `P`、未检件初判分布 `q` 与估计台数始终只按**当前批次**
  的拆检记录计算；新批缺实检样本时照旧撤下估数并提示补检。

## 二、目录结构

```
app/
  estimation.py     # 混淆矩阵、门控、单纯形约束最小二乘（纯 NumPy）
  csv_utils.py      # CSV 解析与校验（≤500 台、表头/类别别名、重复编号）
  storage.py        # 内存批次存储 + 异步锁 + 批次令牌校验（409）
  main.py           # FastAPI 路由（写入接口强制 batch_id）
  static/index.html # 单页前端（原生 JS，3 秒轮询、请求序号防迟到响应）
scripts/
  generate_sample.py# 生成演示 CSV（真实占比 45/35/20 + 混淆噪声）
  smoke_check.py    # 对运行中服务的端到端冒烟（含换批 409 与并发两窗口）
tests/              # pytest：求解器交叉验证、门控、API 全流程、换批与并发
data/sample_machines.csv  # 120 台示例数据
Dockerfile  docker-compose.yml  requirements.txt
```

## 三、启动方式

### Docker Compose（推荐演示）

```bash
docker compose up --build
# 浏览器开两个窗口访问 http://localhost:8000，演示两窗换批：
# 1) 窗口 A 上传 CSV 并登记几台；2) 窗口 B 重传同一 CSV（自动开新批）；
# 3) 回到窗口 A 再点登记 -> 弹出“批次已切换”409 提示并显示当前批次，
#    旧批写入被拒绝、新批同号机器保持未检；4) 在当前批次重新操作即生效。
```

### 本地直接运行

```bash
pip install -r requirements.txt
python scripts/generate_sample.py 120 data/sample_machines.csv   # 可选
uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 1
```

页面操作：上传 `data/sample_machines.csv` → 在机器行点击
「电源/驱动/控制」登记或更正 → 「撤回」使该台重算未检；
上方卡片实时显示**当前批次号**、实检数、未检折算、全批估计、
`P`/`q`/`π` 与 SSE，以及补检提示。另一窗口重新上传会开新批，
旧窗口的下一次写入会收到换批提示并自动同步到当前批次。

### 接口要点

- `POST /api/batch`（multipart 上传）：每次成功都开新批，返回含
  `batch_id` 的快照。
- `GET /api/batch`：返回当前批次快照（含 `batch_id`）。
- `POST /api/machines/{id}/inspect`：JSON 体
  `{"category": "power|drive|control", "batch_id": "..."}`。
- `POST /api/machines/{id}/withdraw`：JSON 体 `{"batch_id": "..."}`。
- 批次号不匹配返回 `409` 与 `current_batch_id`；非法类别/未知机器
  返回 `400`；缺少 `batch_id` 字段返回 `422`。

### CSV 格式

表头支持 `机器编号,初判` 或 `id,initial`（UTF-8，含 BOM 亦可）；
类别支持中英文：`电源/power`、`驱动/drive`、`控制/control`。
编号不可重复，空行容忍，超过 500 台或类别非法返回 400 及中文原因。

## 五、已验证结果

- `pytest`：**22 项全部通过**。求解器与细网格暴力参考解在 12 组随机
  矩阵上交叉验证（SSE 不劣于参考解），并覆盖精确还原、边界（零分量）
  解、缺类/不满秩门控、全检实数等场景；API 测试覆盖上传校验、登记、
  更正、撤回、400/404/409/422 错误路径、`asyncio.gather` 并发，以及
  换批隔离：每次上传开新批（重传同一 CSV 亦然）、旧批令牌写入 409
  且新批同号机器不被污染、新批估数仅按本批记录计算。
- 真实 uvicorn 服务端到端冒烟 **全部 PASS**：上传 120 台 → 满秩样本下
  估数恢复且台数守恒（估数合计=120）→ 更正后实检数同步 → 撤回重算未检
  → 撤回某类全部样本后估数撤下并提示「缺少实检类别样本：控制」→
  补检后恢复 → 两线程并发改不同机器两笔均生效且明细与计数一致 →
  重传同一 CSV 开新批且拆检归零、估数撤下 → 旧批登记/撤回均 409 并
  带回当前批次号、新批同号机器未被污染 → 换批瞬间并发（旧批两笔 409、
  当前批一笔 200）→ 全部拆完返回实数。
- 前端 jsdom 竞态测试 **全部通过**：迟到的旧批 GET/POST 响应（含旧批
  200 快照）不会恢复旧清单/估数；409 后页面提示换批、显示当前批次并
  同步；同批两窗口并发改不同机器两笔都生效并互可见。
- 边界：501 台拒绝、500 台接受；非法类别/未知机器/空上传均返回 400。

   单调编号，没有用户/多租户隔离，同一时刻只保留当前一个批次
   （旧批被替换后不可再访问，其迟到写入一律 409）。

   噪声较大（门控只保证三类齐且满秩，不保证样本量充足）。
4. 估数台数为折算小数（页面保留两位小数），未做取整分配；如需整数备件
   建议，可另加最大余数法取整。

   即为一个轮询周期，期间的写入由后端 409 兜底，不会写错批次。
